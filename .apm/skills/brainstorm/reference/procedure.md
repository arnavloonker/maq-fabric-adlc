# /brainstorm procedure

1. **Scope.** Identify the Git consumer root, intent, branch (architecture, experiment/new workload, or data-product semantics), and allowed environments. Read `maq-project.toon` only for required platform dependencies; a missing unused dependency blocks nothing.
2. **Context.** Read `domain\index.md` and only relevant domain files and `references\` entries. If a story ID is given, read it with `azure-devops-wit_work_item` `get` (and `list_comments` if needed). Treat domain observations as hypotheses unless marked reviewed.
3. **Practices.** Consult /best-practices for each artifact type involved (notebook, pipeline, semantic model, lakehouse, etc.); load only applicable linked pages. Do not recurse. A failed lookup is reported, not hidden.
4. **Hypotheses.** Write each hypothesis, the evidence that would support it, and the evidence that would refute it. Keep success criteria measurable.
5. **Repository.** Inspect code, definitions, and existing models relevant to the hypothesis.
6. **Fabric discovery.** Discover tool schemas, then resolve authorized artifacts with `FabricIQ-DiscoverArtifacts` / `FabricIQ-ResolveFabricItem`. Inspect schemas via `FabricIQ-GetSemanticModelSchema` or the relevant direct Fabric skill/tool binding in the capability matrix.
7. **Bounded evidence.** Run a query only when a specific decision needs it. State its purpose, return at most 250 rows, set a 60-second timeout/budget where supported, use partition filters or sample keys, and prefer aggregates. For data asks profile: candidate grain (row count vs distinct key count), key uniqueness and null rate, join completeness (FULL OUTER JOIN match/orphan counts both sides), fan-out, and sample reconciliations against a known figure. Conclude whether the candidate model answers the requirement without distorting the data. This is exploratory, not a final contract.
8. **Grilling.** For each unresolved decision ask exactly one question, always with a recommended answer and brief reason. Wait for the reply before the next. Test alternatives and success criteria; record rejected options.
9. **Optional DEV experiment.** Only if a hypothesis cannot be settled otherwise: draft the experiment plan (see contract approval rules), preview it, and stop for explicit approval. Execute strictly inside it using prefixed scratch artifacts in DEV. Always run the approved cleanup, verify it, and report any failure. On a write/execution timeout, inspect current state by scoped identifiers before any retry; if inconclusive, stop and report. Never promote the artifact.
10. **Access gaps.** If permission or tooling is insufficient, mark the hypothesis inconclusive and state what access would resolve it. Never fabricate support.
11. **Record.** Create `references\explorations\<id>\findings.md` from `evidence-template.md` (new file, non-destructive). Include source, timestamp, environment, query/definition version, limitations, sensitivity handling. Sanitize examples. Preview any edit to an existing shared file or index and obtain approval. Keep scratch output ignored by Git; local findings are marked unpublished until committed through an approved change.
12. **Report.** Summarize outcomes per hypothesis, choices with evidence, rejected alternatives, candidate models, unknowns, findings path, and any substitutions. Do not publish a story or force `/to-story`; mention that `/approach` specifies the exact change once a direction is selected.
